# ARM 汇编语言基础

汇编语言（Assembly Language）是与特定计算机**指令集架构 (ISA)** 一一对应的、低级的编程语言。它使用人类可读的**助记符 (Mnemonics)**，来表示 CPU 能够直接执行的、二进制的**机器码 (Machine Code)**。对于苹果开发者来说，需要关注的是 **ARM64** 汇编语言。

学习汇编语言，是深入理解“代码究竟是如何在硬件上执行的”这一根本问题的关键。

## 基本构成

一段 ARM64 汇编代码，主要由以下几个部分组成：

*   **指令 (Instructions)**: CPU 可以执行的操作，例如 `MOV` (移动数据), `ADD` (加法)。
*   **伪指令 (Directives)**: 给汇编器（Assembler）的指令，用于控制汇编过程，例如 `.text` (定义代码段), `.data` (定义数据段), `.global` (声明一个全局符号)。
*   **标签 (Labels)**: 一个标签，是某个内存地址的符号名称。它通常用于标记一个函数或一个循环的开始，以便于跳转指令（如 `B`, `BL`）引用。
*   **注释 (Comments)**: 通常以 `@` 或 `//` 开头。

## 核心指令详解

### 1. 数据处理指令

这类指令，用于在**寄存器**之间，进行算术和逻辑运算。

*   **传送指令**
    *   `MOV Rd, Operand`: 将 `Operand` 的值，传送到目标寄存器 `Rd`。`Operand` 可以是另一个寄存器，也可以是一个立即数。
        *   `MOV X0, X1`   ; `X0 = X1`
        *   `MOV X0, #42`  ; `X0 = 42`

*   **算术指令**
    *   `ADD Rd, Rn, Operand`: 加法。 `Rd = Rn + Operand`
    *   `SUB Rd, Rn, Operand`: 减法。 `Rd = Rn - Operand`
    *   `MUL Rd, Rn, Rm`: 乘法。 `Rd = Rn * Rm`

*   **逻辑指令**
    *   `AND Rd, Rn, Operand`: 按位与。
    *   `ORR Rd, Rn, Operand`: 按位或。
    *   `EOR Rd, Rn, Operand`: 按位异或。
    *   `LSL`, `LSR`: 逻辑左移、逻辑右移。

### 2. 内存访问指令 (Load/Store Architecture)

ARM 是一种 **Load/Store** 架构。这意味着，只有 `LDR` 和 `STR` 这两类指令，可以访问内存。任何其他的计算，都必须在寄存器之间进行。

*   **`LDR Rd, [Rn, #offset]` (Load Register)**
    *   **作用**: 从内存中，**加载**一个值，到寄存器中。
    *   **示例**: `LDR X0, [SP, #8]`
        *   计算内存地址：取 `SP` 寄存器的值，加上 8 个字节的偏移量。
        *   从这个计算出的内存地址中，读取一个 64 位的值。
        *   将这个值，写入到 `X0` 寄存器中。

*   **`STR Rd, [Rn, #offset]` (Store Register)**
    *   **作用**: 将一个寄存器的值，**存储**到内存中。
    *   **示例**: `STR X0, [SP, #8]`
        *   计算内存地址：取 `SP` 寄存器的值，加上 8 个字节的偏移量。
        *   将 `X0` 寄存器中的值，写入到这个计算出的内存地址中。

*   **`LDP` / `STP` (Load/Store Pair)**
    *   `LDP` 和 `STP` 是 ARM64 的一个特色指令，它们可以**一次性地**，加载或存储**一对**（两个）寄存器。这在函数序言和尾声中，用于保存和恢复调用者寄存器时，非常高效。
    *   **示例**: `STP X29, X30, [SP, #-16]!`
        *   这是一个“预变址 (pre-index)”的 `STP` 指令。`!` 表示在操作完成后，会更新 `SP` 寄存器的值。
        *   它等价于：
            1. `SUB SP, SP, #16`  ; `SP` 先减 16
            2. `STR X29, [SP]`      ; 将 `X29` 存到新的 `SP` 位置
            3. `STR X30, [SP, #8]`  ; 将 `X30` 存到 `SP + 8` 的位置

### 3. 分支与控制流指令

这类指令，用于改变 `PC` (程序计数器) 的值，从而实现循环、条件判断和函数调用。

*   **`B <label>` (Branch)**
    *   **作用**: 无条件跳转。立即将 `PC` 的值，设置为 `<label>` 所在的地址。

*   **`BL <label>` (Branch with Link)**
    *   **作用**: **调用函数**。
    *   **工作流程**:
        1.  将**下一条指令的地址**（即函数的“返回地址”），保存到**链接寄存器 `LR` (`X30`)** 中。
        2.  然后，无条件跳转到 `<label>` 所在的函数地址。

*   **`RET` (Return)**
    *   **作用**: **从函数返回**。
    *   **工作流程**: 它通常会无条件地，跳转到链接寄存器 `LR` (`X30`) 中，所存储的地址。

*   **比较与条件分支**
    *   `CMP Rn, Operand`: 比较指令。它会用 `Rn` 的值，减去 `Operand` 的值，然后根据结果（是正、是负、还是零），来更新特殊的状态寄存器中的**条件标志位**（如 Z-zero, N-negative）。
    *   `B.<cond> <label>`: 条件跳转。在 `CMP` 指令之后，可以使用带条件的 `B` 指令。
        *   `B.EQ <label>`: 如果结果为 0 (Equal)，则跳转。
        *   `B.NE <label>`: 如果结果不为 0 (Not Equal)，则跳转。
        *   `B.GT <label>`: 如果结果为正 (Greater Than)，则跳转。
        *   `B.LT <label>`: 如果结果为负 (Less Than)，则跳转。

## 函数调用栈 (The Stack)

栈是一块特殊的内存区域，它以“**后进先出 (LIFO)**”的方式工作。在进行函数调用时，栈被用来：
*   保存函数的**返回地址**。
*   保存需要被保护的、**调用者的寄存器**（因为寄存器是所有函数共享的）。
*   为函数的**局部变量**，分配存储空间。
*   传递**多于 8 个**的函数参数。

每一次函数调用，都会在栈上，创建一个新的“**栈帧 (Stack Frame)**”。

*   **函数序言 (Prologue)**: 在一个函数的开始，通常会有一段标准化的汇编代码，用于创建新的栈帧。它会：
    1.  将 `SP` 向下移动，为当前函数，预留出栈空间。
    2.  使用 `STP` 指令，将调用者的 `FP` (`X29`) 和 `LR` (`X30`)，保存到栈上。
    3.  将当前的 `SP` 值，保存到 `FP` 中，以建立新的栈帧指针。

*   **函数尾声 (Epilogue)**: 在函数 `RET` 返回之前，会有一段与序言相对应的代码，用于销毁当前的栈帧。它会：
    1.  使用 `LDP` 指令，从栈上，恢复调用者的 `FP` 和 `LR`。
    2.  将 `SP` 向上移动，释放栈空间。

## 总结

阅读 ARM 汇编，就像是在阅读 CPU 的“思维过程”。

*   **核心是寄存器**: 所有的数据处理，都在寄存器之间进行。
*   **内存访问是独立的**: 只有 `LDR` 和 `STR`，可以与内存打交道。
*   **函数调用是标准化的**: 通过 `BL` 和 `RET` 指令，以及对 `LR`, `FP`, `SP` 寄存器的标准化操作，来实现函数的调用和返回。

虽然汇编语言的语法，比高级语言要繁琐得多，但其指令的数量和类型，都是有限的。通过掌握上述最核心的指令和概念，并结合调试器，进行反复的实践和对照，你就能够逐步地，揭开高级语言背后，那层最神秘、也最接近硬件本质的面纱。
