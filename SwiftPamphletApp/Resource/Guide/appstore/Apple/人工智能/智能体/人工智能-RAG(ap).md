# AI 架构：检索增强生成 (RAG)

检索增强生成（Retrieval-Augmented Generation, RAG）是一种强大的、用于将大型语言模型（LLM）与外部的、私有的知识库相结合的架构模式。它旨在解决 LLM 的两个核心局限性：

1.  **知识截止日期**: LLM 的知识被“冻结”在其训练数据的截止日期。它不知道在那之后发生的任何事情。
2.  **无法访问私有数据**: LLM 对你的公司内部文档、个人笔记或任何未公开在互联网上的信息一无所知。

RAG 通过一种“开卷考试”的方式，让 LLM 能够访问并利用这些外部知识，从而生成更准确、更相关、更可信的答案。

## 核心理念：检索 + 生成

RAG 的工作流程分为两个主要阶段：

1.  **检索 (Retrieval)**: 当用户提出一个问题时，系统**不**直接将问题发送给 LLM。相反，它首先将用户的问题作为一个**查询**，去一个外部的知识库（通常是一个**向量数据库**）中，检索出与问题最相关的几个文档片段或信息块。

2.  **生成 (Generation)**: 系统将用户原始的问题和从知识库中检索到的相关信息片段，**一起**打包成一个新的、更丰富的提示词（Prompt），然后将这个提示词发送给 LLM。并要求 LLM：“请**根据我提供的以下上下文信息**，来回答这个问题。”

```mermaid
graph TD
    A[用户提问] --> B{检索器 Retriever}
    B -- 查询 --> C[知识库 (向量数据库)]
    C -- 返回相关文档 --> B
    B -- 增强的提示词 --> D{生成器 Generator (LLM)}
    A -- 原始问题 --> D
    D --> E[最终答案]
```

## RAG 的实现步骤

构建一个 RAG 系统通常涉及两个主要流程：数据索引和实时查询。

### 1. 数据索引流程（离线）

这个流程的目标是将你的私有文档库，转换为一个可被高效检索的向量数据库。

1.  **加载数据 (Load)**: 从你的数据源（如 PDF, Markdown, HTML, Notion, Confluence）中加载原始文档。
2.  **切分文档 (Chunking)**: 将长文档切分成更小的、有意义的、固定大小的文本块（chunks）。一个常见的策略是按段落切分，并允许块之间有一定的重叠，以保留上下文的连续性。
3.  **向量化 (Embedding)**: 使用一个“嵌入模型”（Embedding Model，例如 OpenAI 的 `text-embedding-ada-002`），将每一个文本块都转换成一个高维的数学向量（例如，一个由 1536 个浮点数组成的数组）。这个向量代表了该文本块在语义空间中的“位置”。
4.  **存入向量数据库 (Store)**: 将每个文本块的内容及其对应的向量，一起存储到一个专门的向量数据库（Vector Database）中，如 Pinecone, Chroma, Weaviate, 或 Supabase pgvector。

### 2. 查询与生成流程（在线）

这是当用户实际提问时发生的实时流程。

1.  **向量化查询**: 使用**相同**的嵌入模型，将用户的提问也转换成一个向量。
2.  **向量相似度搜索**: 在向量数据库中，执行一个“相似度搜索”（通常是余弦相似度或点积）。数据库会返回与用户问题向量在语义上最接近的 N 个文本块（例如，最相关的 5 个）。
3.  **构建提示词**: 创建一个提示词模板，将检索到的文本块作为“上下文”，连同用户的原始问题一起，组合成一个完整的提示词。

    ```
    [System Prompt]
    你是一个专业的苹果产品客服。请根据下面提供的上下文信息来回答用户的问题。如果上下文中没有相关信息，就直接说你不知道。

    [Context]
    文档片段 1: ...
    文档片段 2: ...
    文档片段 3: ...

    [User Question]
    用户原始的问题...
    ```

4.  **调用 LLM 生成答案**: 将这个增强后的提示词发送给 LLM，并获取最终的答案。

## RAG vs. 微调 (Fine-tuning)

| 特性 | RAG | 微调 (Fine-tuning) |
| :--- | :--- | :--- |
| **目的** | 让模型掌握**新的事实性知识**。 | 让模型学习一种新的**风格、格式或技能**。 |
| **改变模型？** | **否**。不改变模型本身的任何权重。 | **是**。通过在特定数据集上继续训练，来更新模型的权重。 |
| **知识更新** | **容易**。只需更新向量数据库中的文档即可。 | **困难**。需要重新进行耗时、昂贵的微调过程。 |
| **可解释性** | **高**。可以明确地告诉用户，答案是基于哪些原始文档片段生成的。 | **低**。很难解释为什么模型会生成某个特定的答案。 |
| **“幻觉”问题** | **显著减少**。因为模型被强制要求基于提供的上下文来回答。 | 无法解决。模型仍然可能“编造”它在训练数据中从未见过的事实。 |

**最佳实践**: RAG 和微调是互补的。你可以先对一个模型进行微调，让它学会你的公司特有的沟通风格和术语，然后再将这个微调过的模型，与一个包含你公司最新产品文档的 RAG 系统结合使用。

## 总结

检索增强生成（RAG）是目前将大型语言模型与私有、动态变化的知识库相结合的**最佳实践**和**行业标准**。

*   **核心思想**: 通过“检索-生成”的两步过程，为 LLM 提供“开卷考试”的能力。
*   **优势**: 显著降低了模型产生“幻觉”的风险，提高了答案的准确性和可信度，并且使得知识库的更新变得非常简单。
*   **实现关键**: 
    *   **数据处理**: 合理地切分和向量化你的文档。
    *   **向量数据库**: 选择一个合适的向量数据库来存储和检索信息。
    *   **提示词工程**: 精心设计你的提示词模板，以最好地利用检索到的上下文。

通过构建一个 RAG 系统，你可以将一个通用的、无所不知的 LLM，转变为一个真正理解你特定业务领域、能够提供精准、可靠答案的“领域专家”。
