# AI 辅助开发：高效的 App 开发提示词（Prompts）

将大型语言模型（LLM）作为“结对编程伙伴”时，你向它提问的方式——即**提示词（Prompt）**——直接决定了你获得答案的质量和效率。一个好的提示词应该像一个清晰、完备的需求文档，为 AI 提供所有必要的上下文和指令。

以下是一些在 App 开发（特别是 iOS/SwiftUI）中，经过实践检验的高效提示词模式和范例。

## 核心原则：R.O.L.E.S.

一个优秀的提示词通常包含以下几个元素，可以缩写为 **ROLES**：

*   **R - 角色 (Role)**: 明确指定 AI 应该扮演的角色。这会极大地影响它的回答风格和知识领域。
*   **O - 目标 (Objective)**: 清晰、具体地描述你想要完成的**任务**是什么。
*   **L - 限制 (Limitations/Constraints)**: 告知 AI 需要遵守的规则、限制或技术栈。例如，代码风格、最低系统版本、禁止使用的库等。
*   **E - 示例 (Examples)**: 提供一个或多个“输入-输出”的范例（Few-shot learning），这对于让 AI 理解复杂的格式或逻辑至关重要。
*   **S - 范围/上下文 (Scope/Context)**: 提供所有必要的背景信息，例如相关的代码片段、数据结构、错误日志等。

## 提示词范例

### 1. 生成 SwiftUI 视图代码

**糟糕的提示词**: 
> “创建一个 SwiftUI 列表”

**优秀的提示词**: 
> **角色**: 你是一个资深的 SwiftUI 开发者，精通 iOS 17+ 的 API。
> 
> **目标**: 请为我创建一个 SwiftUI 视图，该视图需要：
> 1.  显示一个联系人列表。
> 2.  在导航栏中有一个“添加”按钮。
> 3.  列表的每一行都应该显示联系人的头像和姓名。
> 4.  整个列表应该是可搜索的。
> 
> **限制**: 
> *   请使用 `NavigationStack`。
> *   列表数据应该来自下面提供的 `Contact` 结构体。
> *   请使用 SF Symbols 作为图标。
> 
> **上下文**: 
> 这是联系人的数据结构：
> ```swift
> struct Contact: Identifiable {
>     let id = UUID()
>     let name: String
> }
> ```
> 请为我生成完整的、可直接在 Xcode Preview 中运行的代码。

### 2. 代码审查与重构

**糟糕的提示词**: 
> “优化我的代码”

**优秀的提示词**: 
> **角色**: 你是一位对代码质量有极高要求的苹果官方 API 评审专家。
> 
> **目标**: 请审查以下这段 Swift 代码，并从以下几个方面提出具体的改进建议：
> 1.  **可读性**: 是否有更清晰的变量命名或代码结构？
> 2.  **性能**: 是否存在潜在的性能瓶颈，例如不必要的循环或内存分配？
> 3.  **API 设计**: 是否遵循了 Swift API 设计准则？
> 4.  **现代化**: 是否有可以使用更现代的 Swift 或 SwiftUI API（例如 `async/await` 或 `.onChange`）来替代的旧写法？
> 
> **限制**: 请以项目符号列表的形式给出你的建议，并为每个建议提供“修改前”和“修改后”的代码对比。
> 
> **上下文**: 
> ```swift
> // ... 粘贴你的代码片段 ...
> ```

### 3. 解释错误信息

**糟糕的提示词**: 
> “我的代码崩了”

**优秀的提示词**: 
> **角色**: 你是一个经验丰富的 iOS 调试专家，精通 LLDB 和内存管理。
> 
> **目标**: 我的应用在运行时发生了崩溃，请帮我分析以下错误日志，并解释可能的原因和解决方法。
> 
> **限制**: 请用简单易懂的语言解释，并按可能性高低列出 1-3 个最可能的原因。为每个原因提供一个具体的排查步骤或代码修复建议。
> 
> **上下文**: 
> 这是 Xcode 调试控制台输出的完整错误信息：
> ```
> // ... 粘贴完整的错误日志，包括线程回溯堆栈 ...
> ```
> 这是导致崩溃的相关代码片段：
> ```swift
> // ... 粘贴相关的代码 ...
> ```

### 4. 学习新技术

**糟糕的提示词**: 
> “教我 Combine”

**优秀的提示词**: 
> **角色**: 你是一位善于教学的 Swift 导师，能够将复杂的概念分解为简单的步骤。
> 
> **目标**: 我是一个有一定 Swift 基础的开发者，但对 Combine 框架完全不了解。请为我解释 Combine 的核心概念，特别是 `Publisher`, `Subscriber`, 和 `Operator` 的作用。
> 
> **限制**: 
> *   请使用一个简单的、生活中的比喻（例如，自来水厂和水管）来解释它们之间的关系。
> *   请提供一个完整的、可以运行的 Swift 代码示例，演示如何使用 Combine 来处理一个网络请求，并在主线程上更新 UI。
> *   最后，请用一个表格总结 Combine 与现代的 `async/await` 在处理异步任务上的主要区别。

## 总结：将 AI 视为你的初级程序员

你可以将 AI 想象成一个非常有才华、知识渊博，但缺乏项目背景和具体上下文的初级程序员。你需要像指导一个真实的团队成员一样，向它提供清晰、明确、无歧义的指令。

*   **提供完整的上下文**，是获得高质量回答的最关键一步。
*   **明确你的要求**，包括角色、目标和输出格式。
*   **通过范例来引导**，特别是在处理复杂或独特的任务时。
*   **保持迭代**，将与 AI 的对话视为一个持续的、共同解决问题的过程。

通过掌握这些高效的提示词技巧，你可以将 AI 从一个简单的“问答机器人”，转变为一个能够深度融入你开发工作流的、强大的“编程伙伴”。
