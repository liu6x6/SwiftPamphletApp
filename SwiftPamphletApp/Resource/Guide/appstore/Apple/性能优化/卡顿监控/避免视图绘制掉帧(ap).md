# 避免视图绘制掉帧

在 iOS 开发中，要实现流畅的用户体验，关键在于保证屏幕的刷新率能够稳定地维持在 60 FPS（Frames Per Second，每秒帧数）或更高（对于支持 ProMotion 的设备是 120 FPS）。这意味着，主线程必须在每一帧的时间窗口内（对于 60 FPS 是 16.67 毫秒），完成所有的计算、布局和渲染任务。一旦超过这个时间，就会发生“掉帧”，在视觉上表现为卡顿。

以下是一些在视图绘制层面，避免掉帧的常见优化策略。

## 1. 减少视图层级和复杂度

*   **扁平化视图层级**: 一个过于深、过于复杂的视图层级，会极大地增加布局计算和渲染的开销。应该尽可能地保持视图层级的扁平化。
    *   **反例**: `UIView -> UIView -> UIView -> UILabel`
    *   **正例**: 直接将 `UILabel` 作为顶层 `UIView` 的子视图。
*   **使用轻量级视图**: 在不需要处理用户交互的地方，使用 `CALayer` 来代替 `UIView`，可以节省大量的内存和 CPU 开销。

## 2. 优化布局计算 (Auto Layout)

*   **避免不必要的约束更新**: 不要频繁地、动态地添加、删除或修改约束。如果需要实现动画，优先考虑修改约束的 `constant` 属性，而不是移除和重建约束。
*   **使用 `UIStackView`**: 对于线性的、规则的布局，使用 `UIStackView` 通常比手动设置大量的约束，性能更高，代码也更简洁。
*   **权衡 Auto Layout 与 `frame` 布局**: 对于那些布局非常复杂、或者需要频繁变动的列表 `Cell`，如果 Auto Layout 成为了性能瓶颈，可以考虑回归到手动计算 `frame` 的方式。通过在后台线程提前计算好所有元素的 `frame`，并在主线程直接应用，可以极大地减轻主线程的布局压力。

## 3. 避免离屏渲染 (Offscreen Rendering)

离屏渲染是指，当一个视图的效果无法通过一次绘制就完成时，系统会先在后台（离屏）的一个独立的图像上下文中，进行一次额外的渲染，然后再将结果拷贝到屏幕上。这个过程会带来额外的 GPU 开销和上下文切换，是导致性能问题的常见原因。

*   **常见的触发离屏渲染的操作**:
    *   **圆角 (Corner Radius)**: 当同时设置了 `cornerRadius` 和 `masksToBounds` (或 `clipsToBounds`) 时。
    *   **阴影 (Shadow)**: 特别是当 `shadowPath` 未被指定时。
    *   **遮罩 (Mask)**: 使用 `mask` 属性。
    *   **光栅化 (Rasterization)**: 将 `shouldRasterize` 设置为 `true`。

*   **优化策略**:
    *   **圆角优化**: 
        *   对于 `UIImageView`，可以让设计师提供带圆角的图片。
        *   对于简单的背景色圆角，可以通过在后台线程，用 `Core Graphics` 绘制一张带圆角的图片，然后将其作为 `contents` 赋值给 `CALayer`。
    *   **阴影优化**: 务必为需要添加阴影的视图，指定一个明确的 `shadowPath`。这可以告诉 GPU 阴影的确切形状，避免其进行昂贵的离屏计算。
        ```swift
        myView.layer.shadowPath = UIBezierPath(rect: myView.bounds).cgPath
        ```
    *   **避免不必要的 `clipsToBounds`**: 只有在确实需要裁剪子视图时，才将 `clipsToBounds` 设置为 `true`。

## 4. 避免透明与混合 (Blending)

*   **不透明的视图**: 尽可能地将视图的 `opaque` 属性设置为 `true`，并为其设置一个不透明的 `backgroundColor`。这会告诉渲染系统，这个视图后面的任何内容，都不需要被绘制，从而减少不必要的 GPU 计算。
*   **避免透明背景**: 尽量避免使用带有 Alpha 通道的颜色作为背景色。

## 5. 异步绘制与栅格化

*   **异步绘制**: 对于内容极其复杂、绘制耗时非常长的自定义视图（例如，一个富文本编辑器、一个复杂的图表），可以考虑采用异步绘制的策略。即，在后台线程，使用 `Core Graphics` 将视图的内容，预先绘制到一个位图（`UIImage`）中，然后在主线程，只将这张已经绘制好的图片，作为 `CALayer` 的 `contents` 显示出来。这样，主线程就从繁重的绘制工作中被解放了出来。

*   **栅格化 (`shouldRasterize`)**: 对于那些内容复杂、但本身不常发生变化的视图（例如，一个包含了许多子视图的复杂 `Cell`），可以将其 `layer.shouldRasterize` 属性设置为 `true`。这会强制系统将这个视图，预先渲染成一张位图并缓存起来。在之后，只要这个视图不发生变化，系统就可以直接使用这张缓存的位图，而无需再重新渲染其所有的子视图。这是一种用空间（内存）换时间（CPU/GPU）的策略，需要谨慎使用。

## 6. 使用 Instruments 进行分析

*   **Core Animation**: 这个工具可以实时地显示屏幕的刷新率（FPS），并高亮显示那些发生离屏渲染或图层混合的区域，帮助你快速地定位到渲染性能的瓶颈。
*   **Time Profiler**: 用于分析主线程的 CPU 使用情况，找出那些耗时的函数调用。

## 总结

保证视图绘制的流畅性，核心在于**减轻主线程和 GPU 的负担**。

*   **CPU 层面**: 简化视图层级，优化 Auto Layout，采用异步绘制。
*   **GPU 层面**: 避免不必要的离屏渲染和图层混合。

通过遵循这些原则，并结合 Instruments 工具进行针对性的分析和优化，我们可以有效地避免掉帧，为用户提供如丝般顺滑的滚动和交互体验。
