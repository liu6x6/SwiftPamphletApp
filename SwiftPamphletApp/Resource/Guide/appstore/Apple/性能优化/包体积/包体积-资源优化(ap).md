# 包体积优化：资源优化

在 App 的包体积构成中，除了可执行文件（代码和库）之外，资源文件（如图片、音频、视频、数据文件等）通常占据了相当大的比重。因此，对资源文件进行有效的管理和优化，是包体积治理中不可或缺的一环。

## 1. 图片资源优化

图片通常是资源中的“大头”。

### 1.1 使用 Asset Catalogs

这是苹果官方推荐的、管理图片资源的最佳实践。

*   **App Slicing**: 将所有图片资源放入 `.xcassets` 文件中，可以让 App Store 在分发应用时，自动地进行“切片”（Slicing）。这意味着，用户的设备只会下载其屏幕分辨率（`@2x`, `@3x`）和显示色域所需的、最合适的图片版本，而不会下载其他不必要的图片资源。
*   **HEIC 格式**: 对于照片类的大图，可以考虑使用 HEIC 格式。相比于传统的 JPEG，HEIC 可以在保持相近画质的情况下，将文件体积减小约 50%。
*   **向量图 (PDF/SVG)**: 对于那些简单的、纯色的图标或背景图，优先使用向量图格式（在 Asset Catalogs 中，可以将图片设置为“Single Scale”，并提供 PDF 版本）。向量图可以无限缩放而保持清晰，并且通常比提供 `@1x`, `@2x`, `@3x` 三套 PNG 文件所占用的空间要小。

### 1.2 图片压缩

在将图片资源添加到项目之前，应该先使用工具对其进行无损或有损压缩。

*   **工具**: 
    *   **ImageOptim**: 一个非常流行的、免费的 Mac 应用，可以对 PNG, JPEG, GIF 等格式进行无损压缩。
    *   **TinyPNG / TinyJPG**: 在线的图片压缩服务，压缩率很高。
*   **原则**: 在保证视觉效果可以接受的前提下，尽可能地提高压缩率。

### 1.3 动态下载与缓存

对于那些非首屏必须的、或者内容会动态更新的图片（如用户头像、商品图片、活动 Banner），不应该将其打包在 App 内部。正确的做法是：

1.  在应用运行时，从服务器动态地下载这些图片。
2.  在本地，使用如 `SDWebImage`, `Kingfisher` 等第三方库，对下载的图片进行缓存（内存缓存和磁盘缓存），以避免重复下载。

## 2. 音频和视频资源优化

音频和视频文件通常体积巨大，是优化的重点对象。

*   **选择合适的编码和码率**: 在导出音视频文件时，选择合适的编码格式（如音频的 AAC, 视频的 H.264/H.265）和码率（Bitrate）。在保证用户体验可以接受的前提下，尽量降低码率。
*   **流式播放 (Streaming)**: 对于较长的音频或视频，绝对不能将其完整地打包在 App 内。应该将其部署在服务器或 CDN 上，在应用中通过 `AVPlayer` 进行流式播放。
*   **按需资源 (On-Demand Resources)**: 对于一些必须离线使用的、非核心的音视频资源（例如，游戏中的背景音乐、特定关卡的视频教程），可以使用 ODR 技术，让用户在需要时再进行下载。

## 3. 数据文件优化

App 中可能包含一些内置的数据文件，如 JSON, XML, Plist, SQLite 数据库等。

*   **选择合适的格式**: 
    *   对于结构化数据，使用二进制格式（如 `NSKeyedArchiver` 归档后的文件、或二进制 Plist）通常比文本格式（如 JSON, XML）体积更小，解析速度也更快。
    *   如果数据量巨大，可以考虑使用像 `Core Data` 或 `SQLite` 这样的数据库，它们在存储和查询上都经过了高度优化。
*   **数据压缩**: 对于一些大的文本或数据文件，可以在打包前，先对其进行压缩（如 `zip`, `gzip`），然后在应用首次启动时，将其解压到沙盒的缓存目录中使用。

## 4. 清理无用资源

与清理无用代码一样，定期地清理项目中不再被任何地方引用的无用资源，也是一项非常重要的工作。

*   **工具**: 可以使用一些第三方的脚本或工具（如 `LSUnusedResources`），来扫描项目，找出那些存在于项目目录或 Asset Catalogs 中，但从未在代码或 XIB/Storyboard 中被引用的资源文件。
*   **人工审查**: 定期地、人工地检查项目中的资源文件，特别是那些命名不规范、或看起来很陈旧的资源，确认它们是否仍在使用。

## 总结

资源优化是包体积治理中，投入产出比最高的一个环节。其核心思想是：**按需加载，精简内容**。

1.  **图片**: 全面使用 **Asset Catalogs**，善用 **HEIC** 和**向量图**，并在打包前进行**压缩**。
2.  **音视频**: 采用**流式播放**，并选择合适的**编码和码率**。
3.  **数据**: 优先使用**二进制格式**或**数据库**，并考虑在必要时进行**压缩**。
4.  **大宗资源**: 对于所有非首屏必须的大型资源，都应该采用**动态下载**或 **On-Demand Resources** 的方式，进行按需加载。
5.  **清理**: 定期地**清理无用资源**，保持项目的整洁。

通过对资源文件的精细化管理和优化，我们可以极大地减小 App 的包体积，提升用户的下载和安装体验。
