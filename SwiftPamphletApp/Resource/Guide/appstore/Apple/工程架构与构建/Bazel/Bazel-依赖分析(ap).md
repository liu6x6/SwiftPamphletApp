# Bazel 中的依赖分析

依赖分析是 Bazel 构建系统的核心功能之一。Bazel 通过静态分析源代码和 `BUILD` 文件，构建一个完整、精确的项目依赖关系图（Dependency Graph）。这个依赖图是 Bazel 实现其三大核心优势——**正确性、高性能和可复现性**——的基础。

## 为什么依赖分析如此重要？

1.  **增量构建 (Incremental Builds)**: Bazel 通过依赖图，可以精确地知道当某个文件发生变化时，哪些目标（targets）需要被重新构建，而哪些可以安全地从缓存中复用。如果一个底层库没有变化，那么所有依赖于它的上层模块都无需重新编译。

2.  **并行执行 (Parallel Execution)**: 依赖图清晰地揭示了哪些构建任务之间没有依赖关系，可以安全地并行执行。Bazel 会利用这一点，在多核处理器上最大限度地并行化构建任务，从而大大缩短编译时间。

3.  **沙盒化与密封性 (Sandboxing & Hermeticity)**: Bazel 在执行每个构建动作（如编译一个 Swift 文件）时，都会在一个沙盒（sandbox）中进行。这个沙盒只包含在 `BUILD` 文件中明确声明的输入文件和依赖项。这确保了构建过程是“密封的”（hermetic），即不受构建环境（如开发者机器上安装的工具版本）的影响，从而保证了构建结果的可复现性。

4.  **架构治理 (Architecture Governance)**: 清晰的依赖图使得架构师和开发者能够轻松地分析和审查项目的结构，防止不合理的依赖（如循环依赖、跨层调用）的产生。

## Bazel 如何进行依赖分析？

Bazel 的依赖分析过程主要分为两个阶段：

### 1. 加载阶段 (Loading Phase)

*   **解析 `BUILD` 文件**: Bazel 从你要构建的目标开始，递归地解析其所在的 `BUILD` 文件以及其 `deps` 属性中声明的所有依赖项的 `BUILD` 文件。
*   **创建目标图 (Target Graph)**: 在这个阶段，Bazel 会在内存中创建一个由所有相关目标（targets）构成的图。这个图描述了目标之间的依赖关系，但还不包含具体的文件和构建动作。

### 2. 分析阶段 (Analysis Phase)

*   **规则实现 (Rule Implementation)**: Bazel 会执行每个目标对应的规则（Rule）的实现函数（例如 `swift_library` 或 `ios_application` 的实现）。
*   **创建动作图 (Action Graph)**: 在这个阶段，规则的实现函数会告诉 Bazel 为了构建这个目标，需要执行哪些具体的“动作”（Actions）。一个动作是一个需要执行的命令，例如“用 swiftc 编译器编译这三个 .swift 文件，生成一个 .o 文件”。每个动作都明确地声明了它的输入文件（inputs）和输出文件（outputs）。
*   **构建文件依赖图**: 通过分析所有动作的输入和输出，Bazel 最终构建出一个精确到**单个文件**级别的依赖关系图。这个图是最终决定哪些任务需要被执行的依据。

## 依赖类型

在 `BUILD` 文件中，`deps` 属性是最常见的依赖声明方式。但根据规则的不同，还可能存在其他类型的依赖：

*   **`srcs`**: 目标的源文件。
*   **`hdrs`**: 目标的头文件（主要用于 C/C++/Objective-C）。
*   **`data`**: 目标在运行时需要的数据文件（如配置文件、测试数据）。
*   **`toolchains`**: 构建该目标所需的工具链（如特定版本的 Swift 编译器）。
*   **`plugins`**: 编译器插件（如 Swift Macro）。

Bazel 的严格性在于，如果你的代码 `import` 了一个模块，或者使用了一个工具，但没有在 `BUILD` 文件的相应属性中明确声明这个依赖，构建就会失败。这保证了依赖图的**完整性和正确性**。

## 分析依赖的工具：`bazel query`

Bazel 提供了 `bazel query` 命令，这是一个强大的静态分析工具，允许你对加载阶段生成的目标图进行查询。

*   **查找传递性依赖**: `bazel query "deps(//my:target)"`
*   **查找反向依赖**: `bazel query "rdeps(//..., //my:target)"`
*   **查找依赖路径**: `bazel query "somepath(//from:target, //to:target)"`

（更多详情请参阅 `Bazel-query指令找依赖关系(ap).md`）

## 分析构建性能：`bazel aquery`

`bazel aquery` (action query) 是一个更底层的查询工具，它允许你对**分析阶段**后生成的**动作图**进行查询。这对于调试和优化构建性能非常有用。

你可以用它来回答以下问题：
*   “构建这个目标到底执行了多少个编译动作？”
*   “编译这个文件具体需要哪些输入？”
*   “为什么这个动作没有被缓存？”

**示例**: 查看构建 `//main:app` 所需的所有动作。

```bash
bazel aquery "deps(//main:app)"
```

## 总结

精确而严格的依赖分析是 Bazel 所有高级功能（增量构建、并行执行、远程缓存、可复现性）的基石。

*   **工作原理**: 通过**加载阶段**创建目标图，再通过**分析阶段**创建精确到文件级别的动作图。
*   **严格性**: 所有依赖都必须在 `BUILD` 文件中显式声明，否则构建会失败。这保证了依赖图的完整性。
*   **分析工具**: 
    *   `bazel query`: 用于分析目标之间的**逻辑依赖**关系。
    *   `bazel aquery`: 用于分析构建过程中具体的**动作和文件依赖**关系，是性能优化的利器。

通过理解 Bazel 的依赖分析机制，并善用其提供的查询工具，开发者可以获得对项目架构的深刻洞察力，从而构建出更清晰、更健壮、构建速度更快的复杂应用程序。
