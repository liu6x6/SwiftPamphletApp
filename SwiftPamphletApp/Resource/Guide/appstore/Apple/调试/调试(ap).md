# iOS/macOS 开发调试指南

调试是软件开发过程中不可或缺的一环，它是在代码中发现、定位和修复缺陷（Bug）的过程。一个高效的开发者，必然是一个熟练的调试者。在苹果生态中，Xcode 和相关的工具链为我们提供了一套强大而丰富的调试工具。

本指南将概述在 iOS 和 macOS 开发中（主要使用 Swift）最核心的调试技术和工具。

## 1. 断点 (Breakpoints)

断点是调试的起点。通过在代码的特定行设置一个断点，你可以让程序在该行执行**之前**暂停下来，从而有机会检查当前的状态。

*   **设置/取消断点**: 在 Xcode 的代码编辑器中，单击行号旁边的空白区域即可。
*   **临时禁用/启用**: 右键单击断点，选择 “Disable/Enable Breakpoint”。
*   **条件断点 (Conditional Breakpoints)**: 右键单击断点 -> “Edit Breakpoint...”，在 `Condition` 字段中输入一个表达式（如 `i > 10`）。只有当该表达式为 `true` 时，断点才会被触发。这对于调试循环或频繁调用的函数非常有用。
*   **异常断点 (Exception Breakpoints)**: 在 Xcode 的断点导航器中（`Cmd+8`），点击左下角的 `+` 号，选择 “Exception Breakpoint”。这会在应用中任何地方抛出未捕获的异常时，自动暂停程序，帮助你快速定位到崩溃的源头。
*   **符号断点 (Symbolic Breakpoints)**: 允许你为某个特定的函数或方法名上设置断点，无论它在哪个文件中。例如，你可以为 `-[UIView layoutSubviews]` 设置一个断点，来观察所有视图的布局过程。

## 2. LLDB 调试器

当程序因断点而暂停时，Xcode 的调试控制台会显示 `(lldb)` 提示符。LLDB 是一个强大的命令行调试器，允许你与暂停的程序进行交互。

*   **`po <对象>`**: 打印一个对象的描述。这是最常用的命令。
*   **`p <表达式>`**: 打印一个变量或表达式的值。
*   **`expression <代码>`**: 执行任意 Swift 代码，甚至可以改变变量的值。
*   **流程控制**: `c` (continue), `n` (next), `s` (step), `finish`。

（更多详情请参阅 `LLDB(ap).md`）

## 3. 视图调试 (View Debugging)

当遇到 UI 布局问题时（如视图位置不正确、被遮挡、尺寸错误），视图调试器是你的最佳帮手。

*   **启动方式**: 在应用运行时，点击 Xcode 调试栏中的“Debug View Hierarchy”按钮（一个看起来像三层叠加的矩形图标）。
*   **功能**:
    *   **3D 视图层级**: 以一个可交互的、爆炸式的 3D 模型来展示当前屏幕上所有 `UIView`（对于 SwiftUI，是其背后的 `UIView`）的层级关系。
    *   **属性检查器**: 选中任何一个视图，都可以在右侧的检查器中查看其详细的属性，如 `frame`, `bounds`, `alpha`, 背景色，以及施加在它上面的所有 Auto Layout 约束。
    *   **发现问题**: 视图调试器会自动检测并标记出常见的布局问题，如内容被裁剪、约束冲突等。

## 4. 内存调试 (Memory Debugging)

内存问题（如内存泄漏、循环引用）是导致应用性能下降和崩溃的常见原因。

*   **内存图调试器 (Debug Memory Graph)**: 与视图调试器类似，点击调试栏中的相应按钮，可以冻结应用的当前状态，并显示一个表示所有内存中对象及其相互引用关系的图。如果存在循环引用（两个或多个对象相互持有，导致谁也无法被释放），内存图调试器会清晰地将其标记出来。

*   **Instruments - Leaks**: Instruments 是一个功能更强大的性能分析工具集。其中的 “Leaks” 工具可以实时地检测应用在运行过程中是否发生了内存泄漏。

## 5. 性能分析 (Profiling with Instruments)

当你的应用出现卡顿、掉帧或响应缓慢时，你需要使用 Instruments 来进行性能分析，找到瓶颈所在。

*   **启动方式**: 在 Xcode 中，选择 Product -> Profile (`Cmd+I`)。
*   **常用工具**:
    *   **Time Profiler**: 最常用的性能分析工具。它会定期对应用的所有线程进行采样，统计出每个函数占用的 CPU 时间。通过它，你可以快速找到那些消耗 CPU 最多的“热点”函数。
    *   **Allocations**: 用于追踪内存的分配情况，可以帮你找到哪里创建了大量的对象。
    *   **Core Animation**: 用于调试渲染性能问题。它可以高亮显示那些被频繁重绘（Off-screen rendering）或混合（blending）的图层，这些通常是导致 UI 卡顿的原因。

## 6. 日志与断言

*   **`print()`**: 最简单的调试方式，但在生产代码中应避免过多使用。
*   **`os.Logger` (统一日志系统)**: 苹果推荐的、现代化的日志框架。它允许你定义不同的日志级别（`debug`, `info`, `notice`, `error`, `fault`）和类别，并可以在“控制台 (Console.app)”应用中进行高效的过滤和查看。
*   **`assert(_:_:file:line:)`**: 用于在开发阶段，检查必须为真的条件。如果条件为 `false`，应用会**在 Debug 构建下崩溃**，并显示一条消息。它在 Release 构建下会被自动移除，不会影响线上用户。
*   **`precondition(_:_:file:line:)`**: 与 `assert` 类似，但它在 **Debug 和 Release 构建下都会生效**。如果条件不满足，应用会直接崩溃。它用于检查那些如果不满足就绝对无法继续运行的、关键性的条件。

## 总结

调试是一门科学，也是一门艺术。掌握一套系统性的调试方法，远比无头苍蝇式地 `print` 要高效得多。

1.  **从断点开始**: 使用断点来暂停程序，观察状态。
2.  **与 LLDB 对话**: 使用 `po` 和 `expression` 来深入探索程序的内部。
3.  **可视化 UI**: 使用视图调试器来解决所有布局问题。
4.  **监控内存**: 使用内存图调试器和 Leaks 工具来查找内存泄漏。
5.  **分析性能**: 使用 Time Profiler 来定位性能瓶颈。
6.  **善用日志**: 使用 `os.Logger` 记录关键信息，使用 `assert` 和 `precondition` 来保证代码的健壮性。

通过系统地运用这些工具，你将能够更从容、更高效地面对开发中遇到的各种疑难杂症。
