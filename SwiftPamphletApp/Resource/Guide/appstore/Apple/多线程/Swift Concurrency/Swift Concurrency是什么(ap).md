# 什么是 Swift Concurrency？

**Swift Concurrency（Swift 并发模型）** 是 Apple 在 Swift 5.5（伴随 iOS 15 和 macOS 12）中引入的一项史诗级语言特性。

它的核心目的是：**在编译器层面，提供一种安全、高效、且极其易读的方式来编写异步（Asynchronous）和并行（Parallel）代码。**

## 1. 为什么需要新的并发模型？

在 Swift 5.5 之前，我们在 iOS 开发中处理多线程和异步任务，主要依赖以下两种方式：

1.  **Grand Central Dispatch (GCD) / \`DispatchQueue\`**：这是基于 C 语言的底层 API。它的缺点是极度容易写出“回调地狱（Callback Hell）”，即闭包一层套一层；同时，极其容易因为忘记在闭包里处理错误、或者忘记切换回主线程（\`DispatchQueue.main.async\`）而导致 App 崩溃或卡死。
2.  **Combine / 响应式编程**：虽然它解决了回调地狱，但它的学习曲线极其陡峭，对于只想简单发起一个网络请求的开发者来说，显得过于沉重和复杂。

## 2. Swift Concurrency 的核心思想

Swift Concurrency 并不是简单地对 GCD 进行封装，而是对 Swift **语言本身**进行了深度改造。它引入了几个革命性的关键字和概念：

*   **\`async / await\` (异步/等待)**：允许你用写“同步代码”的思维去写“异步代码”。你不再需要传入逃逸闭包（\`@escaping closure\`）来接收网络请求的结果，代码会像一条直线一样从上往下执行，但在等待网络响应时，它**不会阻塞**当前的线程。
*   **\`Task\` (任务)**：异步代码的执行载体。就像以前你需要把代码放进 \`DispatchQueue\` 里一样，现在你把异步代码包装在 \`Task { ... }\` 中启动。
*   **\`Actor\` (演员模型)**：终结数据竞争（Data Race）的终极杀器。它是一种全新的引用类型（类似 \`class\`），但在编译器级别保证了同一时间只有一个线程可以访问它的内部状态，彻底消灭了多线程读写同一个变量导致的随机崩溃。
*   **结构化并发 (Structured Concurrency)**：允许你像管理普通变量的作用域一样，管理异步任务的层级关系。当父任务被取消时，所有的子任务也会被自动、安全地取消。

## 3. 它带来了哪些改变？

1.  **代码量锐减，可读性暴增**：消灭了嵌套的闭包，错误处理重新回到了大家熟悉的 \`do-catch\` 模式。
2.  **编译期安全**：利用 \`Sendable\` 协议和 \`Actor\`，编译器现在能在你**写代码的时候**，就检查出 90% 以上的多线程数据竞争错误，而不是等 App 上线后出现神秘崩溃。
3.  **极高的运行效率**：底层的线程池（Thread Pool）被完全重写，它会根据设备的 CPU 核心数动态分配线程。线程的切换（Context Switch）变成了轻量级的协程（Coroutine）切换，性能开销远低于以前 GCD 的线程调度。
